# Systar 技术概览

> **版本**: 1.1
> **日期**: 2026-06-07

---

## 一、项目背景

Systar 是一个通用的 IoT 工业监控运维系统，源自多年智慧园区/工业监控场景的自研实践沉淀。核心能力包括多协议插件式扩展、设备/节点监控、基于规则的告警配置、流水线并行调度等。

Systar 的核心目标：IoT 核心业务逻辑保持精炼稳定，补齐权限管理、运维工单等管理短板，实现轻量部署、架构解耦，兼顾运维需求与未来扩展（AI 智能分析、三维数字孪生），拒绝过度设计和复杂架构。

**架构选择**：项目采用**独立单体架构**——Systar 后端自包含全部能力（IoT 核心 + 运维业务 + 系统管理），前端为独立 Vue3 项目。这一架构简化了部署和运维，避免了多系统间的接口代理开销。

---

## 二、整体架构

采用**独立单体 + 独立前端**的简洁架构，核心原则是"IoT 核心纯净隔离、业务模块垂直切片"，不引入微服务组件，保持架构简洁可控。

### 2.1 架构核心逻辑

一个后端单体服务承载全部业务能力，前端独立部署，通过 REST API + WebSocket 交互。后端内部通过模块化和 DIP 原则保持核心引擎与业务扩展的解耦。

### 2.2 架构分层

- **前端层**：独立 Vue3 + Element Plus 项目（`frontend/`），11 个页面覆盖监控运维全场景，直连 Systar 后端 API
- **后端服务层**：单一 Spring Boot 应用，内部分为 4 个核心模块 + 4 个扩展模块：
  - **核心模块**（`core/`）：IoT 监控引擎、数据访问、协议驱动、通用工具
  - **扩展模块**（`extensions/`）：REST API/启动入口、WebSocket 推送、运维业务、系统管理
- **数据层**：单库部署，按模块分表前缀（`t_` 前缀统一），MySQL 生产 / H2 开发测试
- **支撑层**：Nginx（可选，前端部署和反向代理）

### 2.3 系统交互逻辑

前端直连 Systar 后端（端口 8081），REST API 用于数据查询和业务操作，WebSocket 用于监测值和告警消息的实时推送。JWT Token 用于鉴权。

┌─────────────┐     REST API      ┌──────────────────────────────┐
│   Vue3 前端  │ ──────────────→   │     Systar 后端 (8081)       │
│  (5173)     │ ←────────────── │                              │
│             │     JSON Response │  ┌──────────────────────┐   │
│             │                   │  │  core/               │   │
│             │     WebSocket     │  │  ├─ monitor-core     │   │

                                  │  ┌──────────────────────┐   │
                                  │  │  extensions/         │   │
                                  │  │  ├─ server (API)     │   │

## 三、技术选型

选型核心原则：轻量、稳定、兼容现有 IoT 系统、预留未来扩展，围绕"不复杂、可落地、长期可维护"展开。

### 3.1 后端选型

| 组件 | 版本 | 选型理由 |
|------|------|----------|
| Spring Boot | 3.3.6 | 主流框架，生态完善，JDK17 原生支持 |
| JDK | 17 LTS | 长期支持版本，性能和安全性更优 |
| MyBatis-Plus | 3.5.7 | 轻量 ORM，单表 CRUD 高效，复杂查询可用 JdbcTemplate |
| Hutool | 5.8.27 | 通用工具库，减少重复造轮子 |
| Lombok | — | 样板代码简化 |
| JaCoCo | 0.8.12 | 测试覆盖率统计 |

### 3.2 前端选型

| 组件 | 版本 | 选型理由 |
|------|------|----------|
| Vue | 3.4 | 渐进式框架，Composition API 适合复杂交互 |
| Element Plus | 2.5 | 企业级 UI 组件库，表单/表格/对话框开箱即用 |
| ECharts | 5.5 | 图表可视化，监控大屏和趋势图 |
| Pinia | 2.1 | 状态管理，替代 Vuex，TypeScript 友好 |
| Vue Router | 4.3 | 路由管理 |
| Vite | 5.4 | 构建工具，开发体验优于 Webpack |
| Vitest | 4.1 | 单元测试框架，与 Vite 深度集成 |

不选用 TypeScript：降低开发门槛，适配团队技术基础。

### 3.3 数据层选型

| 组件 | 版本 | 用途 |
|------|------|------|
| MySQL | 8.x | 生产环境数据库 |
| H2 | 2.3.232 | 开发/测试内存数据库，通过 DatabaseDialect 适配器切换 |

### 3.4 支撑组件

| 组件 | 用途 |
|------|------|
| Nginx | 可选，前端部署和反向代理 |
| JWT | 鉴权，Token 包含 user_id + permissions + exp |
| Maven Wrapper | 统一构建环境（Maven 3.9.9），支持离线/内网部署 |

## 四、架构决策说明

1. **独立单体**：后端自包含全部能力（IoT 核心 + 运维 + 系统管理），运维业务和系统管理作为独立扩展模块（systar-ops、systar-system）垂直切片，避免多系统部署复杂度和接口代理开销
2. **DIP 隔离核心引擎**：monitor-core 定义 Repository 接口，systar-data 提供实现，核心引擎不依赖数据层，可独立使用
3. **不引入 Spring Cloud / Redis**：保持单体架构，轻量部署，满足当前规模及未来扩容需求；JWT 无状态鉴权，无需共享会话存储
4. **前端不选用 TS 版**：降低开发门槛，适配团队技术基础
5. **双数据库适配**：DatabaseDialect 适配器模式，MySQL 生产 / H2 开发测试，SQL 脚本按方言独立维护
6. **离线/内网部署**：Maven Wrapper + 项目本地 Maven 仓库（`lib/maven-repo/`），`mvn test -o` 可完全离线构建
